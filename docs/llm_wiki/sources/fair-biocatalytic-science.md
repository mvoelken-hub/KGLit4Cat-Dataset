# FAIR Data and Software in Biocatalytic Science

**Authors:** Jurgen Pleiss  
**Year:** 2024  
**Venue:** ACS Catalysis 14:2709-2718  
**File:** `docs/literature/fair-data-and-software-improving-efficiency-and-quality-of-biocatalytic-science.pdf`

## Abstract
Perspective on FAIR data and FAIR software as prerequisites for efficient, reproducible, and scalable biocatalytic science. It argues that high-throughput experimentation and machine learning create a data-management bottleneck unless biocatalytic data, metadata, and software are standardized, machine-readable, reusable, and connected through ELNs, repositories, exchange formats, ontologies, and collaborative software platforms.

## Key Findings
- Biocatalytic data are "big data" because high-throughput and automated experimentation create high volume, heterogeneity, and complexity.
- Reproducibility is limited by missing raw data, incomplete reaction-condition reporting, missing standards, and inaccessible negative data.
- FAIRification requires standardized exchange formats, controlled vocabularies, domain ontologies, ELNs/LIMSs, laboratory automation, repositories, and FAIR software practices.
- The paper lists relevant exchange formats such as AnIML, DEXPI, EnzymeML, JCAMP-DX, mzML, nmrML, SBML, and ThermoML.
- It distinguishes controlled vocabularies from domain ontologies, and discusses ChEBI, ChemFOnt, GO, OBO, RXNO, SBO, BioPortal, OLS, Ontobee, and Ontologies4Chem.
- EnzymeML is presented as a platform for seamless transfer from experiment to modelling to FAIR publication, including raw data parsing, metadata import from ELNs, Python/Jupyter workflows, and repository upload.
- FAIR software is defined through registration, standardized access, interoperability through formats/APIs, documentation, licensing, version control, and citation.

## Relevance
Useful for SIMONE because it connects FAIR data with FAIR software, laboratory automation, ontologies, exchange formats, ELNs, raw data, negative data, and repositories. It supports thesis arguments that LLM extraction workflows need to produce metadata that can be validated, reused, and connected to structured data/software ecosystems rather than only summarized.
