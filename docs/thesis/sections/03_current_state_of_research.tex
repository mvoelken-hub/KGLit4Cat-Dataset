\label{chap:sota}

This chapter reviews research that motivates an \ac{LLM}-supported workflow for semantic metadata extraction from catalytic experiments.
It first discusses \ac{FAIR} metadata in catalysis.
It then introduces application profiles and vocabulary resources.
The chapter also reviews domain-aware information extraction, domain-specific language models, and vocabulary grounding.
The final section identifies the operational gap addressed by the workflow developed in this thesis.

\section{FAIR Metadata for Catalysis}
\label{sec:fair-data-practice-catalysis}

Catalysis research spans heterogeneous subdomains and a value chain from molecular questions to process-level concerns \cite{wulf2021unified}.
This means that catalysis metadata must describe different materials, reactions, methods, instruments, and data products.
Mendes et al.\ describe a data-sharing problem in catalysis and report that available catalysis data often lack standardization and metadata \cite{mendes2025data}.
The \ac{FAIR} principles provide a general frame for this issue by defining findability, accessibility, interoperability, and reusability as goals for scientific data stewardship \cite{wilkinson2016fair}.
In catalysis, these goals also have a direct data-driven motivation.
Mendes et al.\ argue that open data is a foundation for data-driven catalysis \cite{mendes2021opendata}.
Marshall et al.\ describe high-quality data and metadata as requirements for digital catalysis \cite{marshall2023digital}.

Resource-level metadata remains necessary.
Persistent identifiers, repository landing pages, and access protocols help datasets become citable and retrievable \cite{wilkinson2016fair}.
They do not by themselves describe the scientific content of an experiment.
A dataset may be indexed while its scientific content remains hard to search.
Content-level findability therefore needs domain metadata in addition to dataset identifiers.
Several infrastructure efforts address this need at different points in the research data lifecycle.
Repo4Cat focuses on the repository layer.
It describes an \ac{NFDI4Cat} repository with support for storage, versioning, APIs, working spaces, and publication workflows \cite{kushnarenko2025repo4cat}.
The \ac{NOMAD} catalysis plugin moves closer to content-level metadata.
It supports structured upload of experimental catalysis data, aligns metadata with \ac{Voc4Cat} terminology, and supports search over reactions, materials, conditions, and kinetic properties \cite{schumann2025nomad}.
Moshantaf et al.\ place structured data handling earlier in the laboratory workflow.
Their system connects acquisition, analysis, database upload, relationship generation, and API-based exchange in a catalysis laboratory setting \cite{moshantaf2024advancing}.
Related chemistry and materials infrastructure work gives the broader rationale for this shift.
Duke et al.\ argue that spreadsheets and file systems are weak foundations for scalable chemical data management \cite{duke2022datastorage}.
Scheffler et al.\ connect reusable materials data to metadata, ontologies, workflows, provenance, and repository infrastructure \cite{scheffler2022fair}.

For semantic metadata extraction, this means that \ac{FAIR} practice needs a representation layer.
That layer must describe entities, activities, instruments, methods, quantities, units, provenance, and controlled terms.
Application profiles provide structural constraints for such records.
Vocabularies and ontologies provide stable identifiers and semantic relations for the terms used inside them.
The following section therefore focuses on profile and vocabulary resources for extracted catalysis and chemistry metadata.


\section{DCAT-AP+ and ChemDCAT-AP}
\label{sec:dcat-ap-plus-chemdcat-ap}

Semantic metadata modelling combines structure and terminology.
An application profile defines how classes and properties are used in a specific context.
It can also define relations, cardinalities, and value ranges \cite{Hunter2001Combining}.
\ac{DCAT-AP+} is a \ac{LinkML}-based extension of \ac{DCAT-AP} 3.0.
It adds a provenance layer for describing how a dataset was generated and what the dataset is about.
The profile is domain-agnostic.
Domains can import its generic classes and properties and then specialize them in their own application profiles.
The profile documentation identifies \ac{ChemDCAT-AP} as the first such domain profile for chemistry and catalysis research data \cite{stroemert2026chemdcat,dcatapplusDocumentation}.

\ac{DCAT-AP+} separates profile constraints from ontology mappings.
Its \ac{LinkML} classes and slots define usage-specific shapes.
Their \texttt{class\_uri} and \texttt{slot\_uri} mappings refer to external vocabularies.
This makes specialization a schema-level operation.
It does not require every inherited \ac{LinkML} class to become a new \ac{OWL} subclass.
The design allows a domain profile to keep generic mappings or replace them with more specific terms \cite{stroemert2026chemdcat,dcatapplusDocumentation}.

Within this framework, \ac{DCAT-AP+} provides four profile patterns.
\cref{fig:dcat-ap-plus} shows these patterns.
The first pattern is a provenance core.
Plain \ac{DCAT-AP} allows a \texttt{dcat:Dataset} to link to a \texttt{prov:Activity} with \texttt{prov:wasGeneratedBy}.
\ac{DCAT-AP+} turns this into a more structured provenance graph \cite{dcatapplusDocumentation}.
A \texttt{DataGeneratingActivity} is mapped to \texttt{prov:Activity}.
It can point to evaluated entities, evaluated activities, used entities, generated entities, and agentic entities \cite{dcatapplusDocumentation}.
This distinction matters for experimental metadata.
It separates the dataset, the activity that produced it, the scientific object or process that was evaluated, and the resources used or produced during the activity.

Beyond direct data generation, \ac{DCAT-AP+} uses the same provenance pattern to model data-processing chains.
In this part of the profile, the data-analysis shape specializes the data-generating activity shape, so an analysis remains an activity in the provenance graph.
The analysis source-data shape then identifies the data used as input, and the analysis dataset shape identifies the dataset produced by that analysis.
Together, these shapes keep primary data generation and later analysis in one connected chain while still mapping the profile-specific structures to generic \ac{PROV-O} and \ac{DCAT} classes \cite{dcatapplusDocumentation}.

The second pattern records attributes that describe the activities and entities introduced above.
For numerical metadata, the quantitative attribute shape is mapped to \texttt{qudt:Quantity} \cite{qudt2022schema}.
It combines a literal value with a required \texttt{has\_quantity\_type} field, while the unit field is recommended but optional.
For non-numerical metadata, the qualitative attribute shape provides the corresponding representation.
Because both attribute types can be attached to activities, entities, and agentic entities, the profile can describe measurements, settings, identifiers, and categorical observations in a generic form \cite{dcatapplusDocumentation}.

The third pattern supports controlled classification.
It addresses cases where a resource needs both formal ontology typing and lighter vocabulary-based categorization.
\ac{DCAT-AP+} implements this distinction with \texttt{ClassifierMixin}, which adds \texttt{rdf\_type} and \texttt{type} to central shapes.
The \texttt{rdf\_type} slot maps to \texttt{rdf:type} and states that an instance belongs to a formal ontology class.
The \texttt{type} slot maps to \texttt{dcterms:type} and records a controlled term for broader categorization.
This keeps class membership and controlled-vocabulary classification separate while allowing both to be expressed on the same profile structures \cite{dcatapplusDocumentation}.

The fourth pattern adds optional context to the activities described above.
It distinguishes between directive context and environmental context.
\texttt{Plan} is mapped to \texttt{prov:Plan} and represents information such as a method, protocol, or procedure.
\texttt{Surrounding} is mapped to \texttt{prov:Location} and represents the spatial or environmental setting of an activity.
By linking data-generating activities to these shapes, the profile can describe not only what was produced, but also according to which procedure and under which contextual conditions it was produced \cite{dcatapplusDocumentation}.

\ac{ChemDCAT-AP} extends \ac{DCAT-AP+} for chemistry and catalysis research data \cite{chemdcatapDocumentation}.
The profile shows how generic \ac{DCAT-AP+} provenance and attribute patterns can be specialized through \ac{LinkML} inheritance.
ChemDCAT-AP illustrates this with material entities, chemical entities, chemical reactions, reaction roles, chemical identifiers, and quantitative chemistry slots \cite{chemdcatapDocumentation}.
Because downstream profiles import and specialize \ac{DCAT-AP+}, a \ac{DCAT-AP+}-valid draft can serve as a structural starting point for a more specialized profile draft, but additional domain decisions are needed to choose narrower classes, slots, constraints, and mappings \cite{stroemert2026chemdcat,dcatapplusDocumentation}.

\section{Vocabulary Resources}
\label{sec:vocabulary-resources}

Application profiles and vocabularies serve complementary roles in semantic metadata modelling.
An application profile defines the structure of a metadata record, while vocabulary resources provide controlled identifiers for the terms that fill this structure.
A workflow may first identify a value in the source material and place it in the appropriate profile field.
Only afterwards can it decide whether the value should be grounded to a controlled term, for example as a method type, unit, quantity kind, or other classifiable term.
The resources discussed below cover three levels that are relevant for this thesis: broad catalysis terminology, cross-domain quantity and unit semantics, and NMR-specific spectroscopy metadata.

\subsection{Voc4Cat}
\label{sec:voc4cat}

\ac{Voc4Cat} is a community-extended \ac{SKOS} vocabulary for catalysis and related disciplines \cite{david_linke_2023_8313340}.
Its concepts provide resolvable persistent identifiers and textual definitions.
Within \ac{NFDI4Cat}, \ac{Voc4Cat} is used as part of ontology-based research data management for catalysis \cite{nfdi4cat2024whitepaper}.

Because \ac{Voc4Cat} is based on \ac{SKOS}, it supports preferred labels, alternative labels, definitions, notes, semantic relations, and mappings between concepts \cite{w3c2009skos}.
This makes it suitable for controlled classification in metadata records.
A record can refer to a \ac{Voc4Cat} concept without treating the described resource as an instance of an \ac{OWL} class.
For example, \ac{Voc4Cat} contains a concept for \enquote{nuclear magnetic resonance spectroscopy}.
The concept belongs to the area of characterization techniques and has a resolvable URI \cite{david_linke_2023_8313340}.
It can therefore normalize method-level variants such as \texttt{NMR} and \texttt{nuclear magnetic resonance spectroscopy}.

At the same time, \ac{Voc4Cat} does not replace a method-specific spectroscopy vocabulary.
Its NMR concept identifies the characterization method, but it does not provide the detailed acquisition and processing vocabulary needed for observed nuclei, pulse programs, raw signal types, or spectral processing states.

\subsection{NMR Controlled Vocabulary (nmrCV)}
\label{sec:nmr-cv}

\ac{nmrCV} accompanies \ac{nmrML}, an open \ac{XML}-based exchange and storage format for \ac{NMR} data.
\ac{nmrML} can represent raw free-induction decay data, acquisition settings, processing metadata, spectral assignments, chemical structures, and experiment metadata.
It also provides supporting tools such as converters, parsers, validators, repositories, and workflow components for NMR data exchange \cite{Schober2018nmrML}.
The scope of \ac{nmrCV} therefore differs from \ac{Voc4Cat}.
\ac{Voc4Cat} can identify NMR as a catalysis-relevant characterization method.
\ac{nmrCV} can describe spectroscopy-specific acquisition, processing, and data-product concepts \cite{Schober2018nmrML}.

\subsection{Quantities, Units, Dimensions and Types Ontology (QUDT)}
\label{sec:qudt}

\acf{QUDT} provides a semantic model for physical quantities, units of measure, dimensions, numerical values, and related data structures \cite{qudt2022schema}.
It distinguishes between a concrete quantity and a quantity kind.
A quantity has meaning in the context of a specific measurement, whereas a quantity kind is independent of a particular measurement instance \cite{qudt2022schema}.
\ac{QUDT} also defines relations between units and quantity kinds.
The schema includes relations such as \texttt{qudt:\allowbreak hasQuantityKind}, \texttt{qudt:\allowbreak hasUnit}, and \texttt{qudt:\allowbreak applicableUnit} \cite{qudt2022schema}.
These relations can support validation and transformation software.
For example, a program can check whether a frequency value is paired with a frequency unit, or convert between compatible units when the required unit definitions are available.
However, \ac{QUDT} does not determine which scientific object a value describes.
That decision still depends on source evidence and on the target metadata profile.

\section{Domain-Aware Information Extraction}
\label{sec:domain-aware-information-extraction}

Profiles and vocabularies define how metadata can be represented.
They do not automatically supply the metadata values.
In chemistry, relevant information is often distributed across prose, tables, captions, figures, and diagrams \cite{Fan2024OpenChemIE}.
Chemical data management also has to handle heterogeneous raw files, instrument formats, parsers, schemas, and missing metadata in instrument outputs \cite{duke2022datastorage}.
LLM-based chemical extraction reviews describe end-to-end workflows from source collection to structured output and quality assurance \cite{schilling2025text}.

ChemDataExtractor is a foundational example of chemistry-aware information extraction.
It extracts chemical entities, properties, measurements, and relationships from scientific documents \cite{swain2016chemdataextractor}.
Its pipeline uses chemistry-aware tokenization, part-of-speech tagging, named-entity recognition, phrase parsing, and rule-based grammars \cite{swain2016chemdataextractor}.
It also processes paragraphs, captions, and tables at document level \cite{swain2016chemdataextractor}.
This makes it relevant as a precursor to later schema-guided and \ac{LLM}-based extraction systems.

Zhang et al.\ move this domain-aware perspective into catalysis.
They construct an information-extraction benchmark for catalysis literature \cite{zhang2022knowledge}.
Their benchmark covers six entity types.
These are catalyst, reaction, reactant, product, characterization, and treatment \cite{zhang2022knowledge}.
Their system includes article selection, entity extraction, an entity-aware search engine, and co-occurrence-based correlation analysis \cite{zhang2022knowledge}.
This work fits the thesis topic because it targets catalysis-specific categories.
It remains closer to entity extraction and search than to profile-level semantic metadata construction.

CatMiner applies \ac{LLM}-based extraction to heterogeneous catalysis literature.
It extracts user-specified structure--environment--property records \cite{walls2025catminer}.
The method uses domain knowledge injection, iterative prompting, document-wide context handling, and follow-up prompting \cite{walls2025catminer}.
Its evaluation against a handmade database and manual checks show that domain-specific \ac{LLM} extraction still depends on validation and review \cite{walls2025catminer}.
Its error analysis reports issues such as vague catalyst names, unrelated context, and confusion between different temperature roles \cite{walls2025catminer}.
These errors are directly relevant for metadata extraction because they concern semantic placement, not only output formatting.

SPIRES provides a schema-guided approach.
It recursively interrogates an \ac{LLM} according to a user-defined nested schema \cite{caufield2024spires}.
It grounds extracted entities against external ontologies and controlled vocabularies \cite{caufield2024spires}.
The method is designed to assist manual knowledge curation and acquisition \cite{caufield2024spires}.
SPIRES also discusses hallucination and relation-extraction errors as remaining reliability concerns \cite{caufield2024spires}.
This keeps human validation within the extraction workflow.

EDC addresses knowledge-graph construction from text.
It uses three phases called extract, define, and canonicalize \cite{zhang2024edc}.
The method can operate with a predefined schema or induce one from extracted information \cite{zhang2024edc}.
It also retrieves relevant schema elements when a schema is too large for the prompt \cite{zhang2024edc}.
EDC therefore provides a design precedent for separating evidence extraction, schema organization, and canonicalization.

Reac4Cat-Ontology is not an extraction pipeline.
It still matters for extraction because it shows why catalysis roles require explicit semantics.
The ontology models reaction experiments, reaction components, roles, and catalyst relations \cite{behr2024reac4cat}.
It uses \ac{OWL} description logic and general class axioms to infer reaction-role assignments and catalyst participation \cite{behr2024reac4cat}.
For metadata extraction, this reinforces a key distinction.
Detecting a domain term is not the same as assigning it to the correct entity, activity, or role in a structured record.

\section{Domain-Specific Models, Retrieval, and Grounding}
\label{sec:domain-specific-models-retrieval-grounding}

Extraction also depends on language representations.
SciBERT is pretrained on scientific publications.
It improves performance on scientific sequence tagging, sentence classification, and parsing tasks compared with general-domain baselines \cite{beltagy2019scibert}.
MatSciBERT narrows this approach to materials-science literature.
It reports improvements over SciBERT for named-entity recognition, relation classification, and abstract classification \cite{gupta2022matscibert}.
Zhang et al.\ evaluate fine-tuned \acp{LLM} on five chemical text-mining tasks.
The tasks include compound entity recognition and reaction role labelling.
They also include metal-organic framework synthesis extraction, \ac{NMR} data extraction, and reaction paragraph-to-action-sequence conversion \cite{zhang2024chemicaltextmining}.
These studies support a cautious claim.
Scientific terminology, formulas, abbreviations, and role distinctions can benefit from domain-adapted representations or task-specific tuning.

For semantic metadata extraction, this observation also applies to retrieval and grounding.
Vocabulary grounding depends on how source expressions are turned into candidate queries.
It also depends on how nearby vocabulary terms are ranked and selected.
Domain-specific encoders or rerankers may therefore help when source wording, profile fields, and vocabulary labels differ.
This is an inference from the model and grounding literature rather than a result demonstrated for the thesis workflow.
The claim remains a literature-motivated design hypothesis.

Grounding and retrieval solve a narrower problem than profile construction.
They can normalize or disambiguate terms that have already been exposed as candidate values.
They do not decide which entity or activity should own a value.
They also do not decide whether a quantity describes an instrument, a sample, a reaction condition, or a processing step.
That decision depends on source evidence and on the target profile.

The reviewed work therefore suggests a layered view.
ChemDataExtractor emphasizes chemical entities and document-level extraction targets \cite{swain2016chemdataextractor}.
The catalysis benchmark emphasizes domain entities and annotated extraction targets for catalysis literature \cite{zhang2022knowledge}.
CatMiner shows schema-like user targets, domain prompting, context handling, and review in catalysis literature extraction \cite{walls2025catminer}.
SPIRES combines schema-guided extraction with ontology grounding \cite{caufield2024spires}.
EDC separates open extraction, schema definition, and canonicalization \cite{zhang2024edc}.
SciBERT shows this for scientific text processing \cite{beltagy2019scibert}.
MatSciBERT shows it for materials-science text mining \cite{gupta2022matscibert}.
Chemical fine-tuning work shows it for chemical text-mining tasks \cite{zhang2024chemicaltextmining}.
The open question for this thesis is how these layers behave when they are connected for heterogeneous experimental packages.

\section{Research Gap}
\label{sec:research-gap}

The reviewed literature does not indicate a lack of building blocks.
\ac{NFDI4Cat} provides a research-data infrastructure concept for catalysis \cite{wulf2021unified}.
Repo4Cat provides a repository implementation for catalysis-related sciences \cite{kushnarenko2025repo4cat}.
The \ac{NOMAD} catalysis plugin provides structured upload and search for experimental catalysis data \cite{schumann2025nomad}.
\ac{DCAT-AP+} provides generic provenance-rich profile structures \cite{dcatapplusDocumentation}.
\ac{ChemDCAT-AP} specializes those structures for chemistry and catalysis \cite{chemdcatapDocumentation}.
The accompanying paper presents ChemDCAT-AP as a shared foundation for \ac{NFDI4Chem} and \ac{NFDI4Cat} \cite{stroemert2026chemdcat}.
Voc4Cat provides catalysis terminology \cite{david_linke_2023_8313340}.
\ac{NFDI4Cat} frames that vocabulary as part of ontology-based research-data management for catalysis \cite{nfdi4cat2024whitepaper}.
nmrML and nmrCV provide an NMR-specific data and vocabulary layer \cite{Schober2018nmrML}.
ChemDataExtractor provides chemistry-aware extraction from scientific documents \cite{swain2016chemdataextractor}.
Zhang et al.\ provide a catalysis-specific extraction benchmark and pipeline \cite{zhang2022knowledge}.
CatMiner provides an \ac{LLM}-based extraction workflow for heterogeneous catalysis literature \cite{walls2025catminer}.
SPIRES provides schema-guided extraction with ontology grounding \cite{caufield2024spires}.
EDC provides a staged extraction, schema definition, and canonicalization framework for knowledge-graph construction \cite{zhang2024edc}.

The remaining gap is operational integration.
The reviewed systems are strongest when the input is a scientific article, a controlled text corpus, or a schema-guided extraction task over selected passages.
ChemDataExtractor focuses on chemistry literature \cite{swain2016chemdataextractor}.
OpenChemIE focuses on document-level reaction extraction from chemistry literature \cite{Fan2024OpenChemIE}.
Zhang et al.\ focus on catalysis literature \cite{zhang2022knowledge}.
CatMiner also focuses on catalysis literature \cite{walls2025catminer}.
SPIRES focuses on schema-guided knowledge extraction from text \cite{caufield2024spires}.
EDC focuses on knowledge-graph construction from text \cite{zhang2024edc}.
The thesis case instead starts from heterogeneous experimental dataset packages.
Such packages can contain PDFs, spreadsheets, local metadata files, images, instrument exports, supplementary tables, binary resources, and partially structured folders.
Duke et al.\ support this concern at the chemical data-management level by emphasizing parsers, schemas, APIs, and heterogeneous raw files \cite{duke2022datastorage}.
The nmrML paper supports it at the analytical-data level.
It shows that reusable NMR data may require raw data, acquisition parameters, and processing metadata.
It also points to assignments, chemical structures, converters, and validators \cite{Schober2018nmrML}.

A second gap concerns validity and curation.
Schema-valid output is necessary for machine-actionable metadata.
It does not prove scientific correctness.
CatMiner reports extraction errors that involve vague names, unrelated context, and role confusion \cite{walls2025catminer}.
SPIRES reports hallucination and relation-extraction errors as remaining concerns \cite{caufield2024spires}.
Schilling-Wilhelmi et al.\ discuss constrained decoding, domain-specific validation, and quality assurance for \ac{LLM}-based chemical extraction \cite{schilling2025text}.
These sources support a workflow view in which evidence, profile structure, vocabulary grounding, validation, and human review are complementary controls.

This thesis is positioned in that operational integration gap.
It does not propose a new catalysis ontology.
It does not propose a new repository.
It does not claim to provide a fully automated literature database.
Instead, the workflow developed in this thesis connects heterogeneous source handling with evidence-oriented extraction.
It also connects profile projection, semantic review, vocabulary grounding, validation, and artifact-based diagnosis in one prototype workflow.
The contribution is an examination of how existing standards, vocabularies, and extraction ideas can act as constraints.
It also examines how they can act as grounding resources in an \ac{LLM}-supported metadata extraction process.
