This chapter reviews related work and positions the thesis within the existing literature. Its purpose is not to provide a general survey of catalysis data management or language models, but to connect the theoretical background with the workflow design developed in the following chapter.

\section{Standards and Resources for Semantic Metadata}
\label{subsec:semantic-standards-resources}

Several standards and description languages recur throughout Semantic Web workflows. RDFS and OWL provide schema and ontology semantics above RDF: RDFS supports basic class and property descriptions, while OWL supports richer class expressions and logical modelling \cite{w3c2014rdfschema,w3c2012owl2primer}. SKOS is relevant for controlled vocabularies because it represents concept schemes with preferred labels, alternative labels, definitions, and broader or narrower concept relations \cite{w3c2009skos}. SHACL complements these representation languages by validating RDF graphs against declared shapes and constraints, which makes it important for checking whether generated or projected metadata conforms to an expected structure \cite{w3c2017shacl}.

Profile and provenance languages provide a second layer. PROV-O defines a provenance model around entities, activities, and agents, which is useful when metadata must describe how data was generated and by whom or by what device or software \cite{w3c2013provo}. LinkML is a schema modelling framework that can map schema elements to URIs and generate implementation artifacts such as JSON Schema, SHACL shapes, JSON-LD contexts, documentation, and Python/Pydantic classes \cite{linkmlDocumentation,stroemert2026chemdcat}. DCAT-AP belongs to the dataset-catalogue profile family and is relevant when metadata should remain compatible with repository and data-portal descriptions \cite{dcatapplusDocumentation}. In SIMONE, these standards form the background for the following concrete resources: term-level vocabularies for grounding extracted values and profile-level schemas for the final metadata document.

\subsubsection{QUDT}
\label{subsec:qudt}

QUDT, the Quantities, Units, Dimensions and Types vocabulary, provides semantic resources for measurable quantities, quantity kinds, units, dimensions, and related datatypes \cite{qudt2022schema}. In SIMONE it is used for quantitative normalization: extracted values such as temperatures, pressures, times, rates, or conversions are kept as evidence-bearing observations, but their quantity kind and unit can be matched against QUDT quantity-kind and unit resources after those values have been placed in the profile draft. This separates the textual mention in the source package from the normalized semantic identifier needed for comparison and final semantic enrichment.

\subsubsection{Voc4Cat}
\label{subsec:voc4cat}

Voc4Cat is a SKOS-based catalysis vocabulary developed in the NFDI4Cat context to provide shared terms, definitions, labels, and persistent identifiers for catalysis-related sciences \cite{nfdi4cat2024whitepaper,veluvali2025bridging}. Its role in this thesis is qualitative grounding: extracted labels for catalyst types, workflow concepts, material descriptors, or experimental context can be compared against a community vocabulary instead of remaining uncontrolled strings. This is especially relevant for SIMONE because the prototype retrieves candidate vocabulary terms and then records whether a selected URI or an unresolved case should be carried forward.

\subsubsection{CHMO}
\label{subsec:chmo}

The Chemical Methods Ontology (CHMO) describes methods used in chemical experiments and is distributed as an OBO Foundry ontology \cite{chmoOboFoundry}. In the thesis workflow it provides a controlled target for analytical and experimental method labels, for example when a dataset package refers to spectroscopy, chromatography, microscopy, thermal analysis, or other characterization procedures. CHMO therefore supports the distinction between a raw method mention in a file and a reusable semantic method identifier.

\subsubsection{nmrCV}
\label{subsec:nmrcv}

nmrCV is the controlled vocabulary accompanying nmrML, an open markup format for NMR data; the nmrML specification describes the vocabulary as the component used to express NMR terminology in an unambiguous and standardized way \cite{nmrmlSpecification}. In SIMONE it is relevant for NMR-specific qualitative grounding, where method names, acquisition concepts, nuclei, calibration references, or related NMR terms may require a more specialized vocabulary than a general catalysis or chemical-method resource. The workflow therefore treats nmrCV as one of the configurable domain vocabularies queried during qualitative attribute normalization.

\subsubsection{DCAT-AP Plus and ChemDCAT-AP}
\label{subsec:dcat-chemdcat-provo-linkml}

DCAT-AP Plus extends the dataset-catalogue perspective of DCAT-AP with a provenance-oriented layer based on PROV-O and adds patterns for describing data-generating activities, entities, agents, and attributes \cite{dcatapplusDocumentation,w3c2013provo}. ChemDCAT-AP builds on this pattern for chemistry and catalysis by adding domain-specific concepts for chemical entities, reactions, analytical methods, and attributes while remaining compatible with the broader DCAT application-profile ecosystem \cite{stroemert2026chemdcat,chemdcatapDocumentation}. The profile work is implemented through LinkML, which makes the semantic model usable as practical schema artifacts for validation and software integration \cite{stroemert2026chemdcat,linkmlDocumentation}. In this thesis, DCAT-AP Plus and ChemDCAT-AP define where extracted metadata belongs in the profile draft; vocabularies such as QUDT, Voc4Cat, CHMO, and nmrCV then provide term-level grounding for selected fields as the final enrichment step.


\section{Semantic Data Models for Catalysis}
\label{sec:semantic-data-models-catalysis}
The need for semantic data models in catalysis follows from the structure of the experimental data itself. Catalytic performance values are only meaningful when they can be related to catalyst composition and history, reactor setup, reaction conditions, analytical methods, evaluation procedures, and provenance information. Research data infrastructures therefore do not aim at a single isolated database schema, but at a layered semantic infrastructure in which datasets, experimental workflows, chemical entities, reactions, and process-level descriptions can be connected across repositories and laboratories \cite{wulf2021unified,mendes2025data,nfdi4cat2024whitepaper}. In this sense, the state of the art can be understood as a movement from file-centred documentation toward machine-actionable metadata and knowledge graphs.

\input{figures/catalysis_semantic_stack}

A central initiative in this landscape is NFDI4Cat, which frames catalysis research data management as a shared infrastructure problem across homogeneous, heterogeneous, electro-, bio-, and process catalysis. Its proposed data value chain links catalyst-level data, kinetic and transport phenomena, and process description or simulation, because catalysis data often become scientifically useful only when these scales remain connected \cite{wulf2021unified,nfdi4cat2024whitepaper}. Repo4Cat implements this infrastructure perspective as a repository service for catalysis-related datasets. It provides a central access point for publishing and discovering datasets with catalysis-specific metadata and persistent identifiers, while also acknowledging that repository metadata alone cannot capture all scientific meaning unless it is connected to controlled vocabularies, provenance models, and domain ontologies \cite{kushnarenko2025repo4cat,nfdi4cat2025orchestrating}.

At the dataset discovery layer, the most explicit current effort is ChemDCAT-AP. It extends the European DCAT Application Profile through DCAT-AP+, which adds a provenance-oriented layer based on PROV-O, and then specializes this structure for chemistry and catalysis. ChemDCAT-AP introduces classes and patterns for chemical entities, reactions, analytical methods, and domain-specific attributes while remaining compatible with the general DCAT ecosystem \cite{stroemert2026chemdcat,dcatapplusDocumentation,chemdcatapDocumentation}. Its use of LinkML is important because it makes the semantic profile operational for software developers: the model can be rendered into practical artifacts such as JSON Schema, SHACL shapes, JSON-LD contexts, and Python/Pydantic classes \cite{stroemert2026chemdcat,chemdcatapDocumentation}. ChemDCAT-AP therefore addresses a central interoperability problem: catalysis datasets should be discoverable through general data portals while still carrying enough chemical context to support domain-specific search, validation, and reuse.

Below the dataset profile layer, community vocabularies and ontologies provide the terms and relations needed to interpret the metadata. Voc4Cat addresses the vocabulary problem by offering a SKOS-based, community-managed terminology for catalysis-related sciences. It provides stable concepts and definitions that can be referenced from workflows, repository metadata, and knowledge graphs instead of relying on uncontrolled local labels \cite{nfdi4cat2024whitepaper,veluvali2025bridging}. Metadata4Cat complements this vocabulary-oriented approach by focusing on catalysis-specific metadata quality and by modelling entities such as catalysts, reactions, measurements, and experimental settings in a form that can be checked and reused \cite{huskova2025improvement,nfdi4cat2025orchestrating}. Together, these resources show that interoperability requires both human-agreed terms and executable constraints on how those terms may be used.

The ontology landscape itself is not a single vertical stack. Ontologies4Cat surveys and classifies existing ontologies according to their relevance for catalysis research data management, because relevant concepts are distributed across chemical, biological, materials, and process-engineering models whose coverage differs by subdomain \cite{behr2024ontologies4cat}. Reac4Cat models reaction information with description logic and reuses established chemical ontologies such as ChEBI and RXNO to classify reactions and relate them to experimental data \cite{borgelt2025ontology}. Process-oriented ontologies such as OntoCAPE cover another scale by representing chemical-process and plant-level concepts, which becomes relevant when catalyst data are integrated into simulation or process models \cite{wulf2021unified,marquardt2010ontocape}. These examples illustrate the alignment problem around catalyst, reaction, measurement, and process descriptions without implying that one ontology can cover the whole field.

Reporting standards and data-exchange formats form a further layer because they influence whether the necessary metadata are captured at all. In chemistry, NFDI4Chem promotes minimum-information standards such as MIChI to define which contextual information should accompany chemical investigations and to make these descriptions reusable across repositories \cite{steinbeck2020nfdi4chem,steinbeck2023nfdi4chem}. In biocatalysis and enzymology, established efforts such as STRENDA and EnzymeML show a related pattern: minimum reporting guidelines and machine-readable exchange formats are needed together, because completeness criteria alone do not make data computationally reusable \cite{steinbeck2020nfdi4chem,weigmann2026autonomous}. For heterogeneous catalysis, the Data-Friendly Article framework for catalytic methane reforming demonstrates a more publication-oriented route. It proposes structured reporting of activity, stability, characterization, and reaction-condition data so that literature results can be compared and reused more directly \cite{salim2026methane}. These standards are narrower than a comprehensive catalysis ontology, but they are crucial because semantic models cannot recover experimental context that was never reported.

Taken together, these initiatives converge toward a modular architecture rather than a monolithic data model. Repository profiles such as ChemDCAT-AP make datasets findable and interoperable at the catalogue level; vocabularies such as Voc4Cat stabilize terminology; ontologies such as Metadata4Cat, Reac4Cat, Ontologies4Cat, and OntoCAPE-related models add domain semantics and reasoning support; and reporting frameworks define which information should enter the semantic layer in the first place. This modularity is a strength because catalysis spans many materials, reactions, reactors, analytical methods, and modelling scales. It is also a source of complexity, because practical systems must decide which subset of schemas is sufficient for a given workflow and how extracted information should be validated against them.

The immediate problem for this thesis is therefore not the absence of semantic artifacts, but the operational distance between these artifacts and the heterogeneous material from which metadata must be created. Existing initiatives provide important building blocks, but their adoption is uneven, and much catalysis knowledge remains embedded in articles, supplementary information, figures, instrument exports, and local laboratory systems \cite{mendes2025data,diaz2025knowledgegraphs,salim2026methane}. This motivates workflows that can extract candidate metadata from heterogeneous source material, ground it in existing vocabularies and schemas, and keep human validation in the loop before the resulting records are reused as research data.

\section{NLP and LLM-based Extraction Workflows}
\label{sec:nlp-llm-extraction-workflows}
The semantic data models discussed in the previous section define the target structure for reusable catalysis metadata. NLP- and LLM-based extraction workflows address the complementary acquisition problem: how information that is still embedded in publications, supplementary information, tables, figures, patents, or laboratory reports can be transformed into structured records. For catalysis, this is a difficult task because the meaning of a performance value depends on several coupled elements, including catalyst composition and pretreatment, reactor and reaction conditions, analytical method, and the way activity or selectivity was calculated. The goal of current extraction research is therefore not only to summarize papers, but to produce traceable metadata elements that can be normalized, validated, and inserted into repository profiles or knowledge graphs \cite{zhang2022knowledge,diaz2025knowledgegraphs,ding2026scikg}.

\input{figures/nlp_llm_extraction_workflow}

Classical information extraction pipelines usually decompose this task into several stages. A document selection or triage component first identifies literature that is relevant for a target reaction or catalyst class. The text is then parsed and segmented before named entity recognition identifies spans such as catalysts, reactions, reactants, products, treatments, characterization methods, temperatures, pressures, and performance metrics. Relation extraction connects these entities, for example by linking a selectivity value to the corresponding catalyst and operating temperature. CatalysisIE illustrates this pattern for catalysis literature: it combines article selection with annotated full-text extraction and focuses on entity classes such as catalyst, reaction, reactant, product, characterization, and treatment \cite{zhang2022knowledge,diaz2025knowledgegraphs}. Such pipelines are attractive because their intermediate outputs are explicit and can be evaluated against annotated corpora. At the same time, they require domain-specific training data and often transfer poorly when the reaction family, terminology, or reporting style changes \cite{ding2026scikg}.

Transformer-based language models changed the technical basis of these pipelines. Instead of relying mainly on handcrafted lexical patterns, transformer models use self-attention to represent words in their sentence and document context \cite{vaswani2017attention}. Scientific and materials-language models can therefore detect chemical and procedural expressions that depend on context, such as whether a phrase denotes a catalyst material, a support, a product, or an experimental treatment. However, the catalysis literature still exhibits strong domain shift. Models pretrained on general scientific text or broad materials corpora often have to be adapted to catalysis-specific corpora before they perform reliably on catalyst names, operating conditions, and performance relations \cite{zhang2022knowledge,wang2024catalm}. Domain-specific models such as CataLM show the same trend at the LLM level: they are best understood here as evidence that catalyst-domain adaptation improves domain tasks, including entity extraction and expert-oriented question answering, rather than as complete extraction workflows \cite{wang2024catalm}.

Generative LLMs extend extraction workflows by framing metadata extraction as a controlled generation problem. Instead of assigning a fixed label to each token, a model can be prompted to fill a structured schema, answer a sequence of targeted questions, or generate subject--predicate--object statements from an evidence passage. General work on structured information extraction from scientific text demonstrates that LLMs can produce nested, schema-like records when the output format is constrained and the task is formulated carefully \cite{dagdelen2024structured}. SPIRES follows a related idea by using structured prompt interrogation and recursive extraction to populate LinkML-style schemas, thereby connecting LLM output to an explicit knowledge model rather than to free-form prose \cite{caufield2024spires}. In heterogeneous catalysis, CatMiner provides the central domain-specific example. It extracts catalyst names, operating parameters, and performance metrics through a multiturn question-answering workflow and can use follow-up prompts, domain knowledge, memory, and paragraph search to generate structured CSV records from papers \cite{walls2025catminer}. For the present thesis, these studies are relevant less as complete systems to be reproduced than as design patterns: evidence selection, schema-constrained generation, normalization, provenance retention, and post-generation validation.

These LLM-based approaches lower the barrier created by expensive annotation campaigns, but they also shift the main risk. A model may produce plausible but unsupported relations, overgeneralize from nearby text, or mix experimental and computational claims if the workflow does not constrain the answer. Retrieval-augmented generation addresses part of this problem by supplying the model with evidence retrieved from a vector index, document store, or knowledge graph before generation \cite{lewis2020retrieval,diaz2025knowledgegraphs}. In a catalysis workflow, this grounding step can be combined with semantic resources: chemical identifiers help normalize substances, community vocabularies reduce synonym ambiguity, and schema or SHACL constraints can reject records that do not fit the expected structure. For example, a raw mention such as ``Pt/C'' or ``platinum on carbon'' only becomes reusable metadata after the workflow decides whether it refers to the same catalyst entity, which components are specified, and which details remain unknown \cite{diaz2025knowledgegraphs,veluvali2025bridging}.

The most useful workflows therefore combine extraction with normalization and validation. Numerical values must be converted to consistent units, catalyst names may need to be decomposed into composition or support information, and extracted records should retain provenance links to the source passage or table. CatMiner explicitly treats entity normalization as a post-processing step, because extracted catalyst names and numerical values are not yet machine-readable in the form in which they appear in articles \cite{walls2025catminer}. Knowledge graph construction adds another layer: the workflow must decide which extracted entities become nodes, which relations become edges, and how these statements relate to existing ontology classes and repository metadata. This is where the semantic data models of Section~\ref{sec:semantic-data-models-catalysis} become operational constraints for extraction rather than merely documentation artifacts.

The limitations of current systems also show why fully automated extraction remains insufficient for high-quality catalysis metadata. PDF parsing is still brittle for multi-column layouts, tables, chemical notation, captions, and supplementary information, so the input to the model may already be incomplete or distorted \cite{zhang2022knowledge,walls2025catminer}. In addition, the literature itself often omits important contextual information, provides numerical values only in figures, or does not report negative results, which introduces systematic bias into extracted datasets \cite{mendes2025data,takahashi2023catalysts,salim2026methane}. LLMs can sometimes infer implicit context, but such inference is not a substitute for reported evidence. The literature therefore points toward workflows with confidence handling where available, provenance tracking, schema validation, and expert review checkpoints rather than unsupervised ingestion of generated records \cite{rankovic2025uncertainty,kim2025materialsdiscovery}. This connects directly to the following section, where human-in-the-loop validation is considered as a necessary part of semantic metadata extraction.

\section{Human-in-the-loop and Validation Approaches}
\label{sec:human-in-the-loop-validation-approaches}
The preceding sections show that automatic extraction and semantic modelling solve different parts of the same problem. Extraction systems can propose candidate metadata, and schemas can describe how these records should look, but neither step by itself guarantees scientific correctness. Current work therefore treats validation as a layered process in which machine checks, provenance information, confidence estimates, and expert review complement one another. This is especially important for catalysis knowledge graphs, where an erroneous relation between catalyst, condition, and performance value can be propagated into search, comparison, or modelling workflows \cite{diaz2025knowledgegraphs,ding2026scikg}.

Human-in-the-loop strategies are most visible where extraction uncertainty is high. CatalysisIE, for example, relies on annotated training data produced by chemically trained annotators and uses active learning to select uncertain examples for further labelling \cite{zhang2022knowledge,diaz2025knowledgegraphs}. This pattern is useful because expert time is directed toward ambiguous cases rather than spent on every sentence. More recent LLM-based systems require a similar review layer, even if the human task changes from token annotation to checking structured records, resolving ambiguous catalyst names, deciding whether a result is experimental or computational, and correcting relations that span several paragraphs \cite{walls2025catminer}. Human review is therefore not only a final approval step, but also a mechanism for improving the extraction workflow and maintaining the semantic resources on which it depends.

Automated validation provides the first line of quality assurance before a generated record reaches a curator or a knowledge graph. JSON Schema can check whether an extracted record is syntactically well-formed, whether required fields are present, and whether values have the expected datatype or nesting structure. SHACL extends this idea to RDF graphs by validating graph shapes, cardinalities, class memberships, and property constraints \cite{w3c2017shacl}. In the catalysis metadata context, LinkML is particularly relevant because ChemDCAT-AP uses it as a central modelling layer from which JSON Schema, SHACL shapes, JSON-LD contexts, and Python/Pydantic classes can be generated consistently \cite{stroemert2026chemdcat,chemdcatapDocumentation}. These artifacts make the semantic model executable: an extraction pipeline can reject malformed JSON, flag incomplete reaction records, or prevent RDF statements that violate declared constraints.

For this reason, validation has to be separated into several levels. Syntactic validity asks whether the output is well-formed and schema-conformant. Semantic validity asks whether extracted terms are grounded in appropriate identifiers, vocabularies, or ontology classes. Evidential validity asks whether the structured statement is supported by a source passage, table, file, or other traceable evidence. Domain-expert acceptance finally asks whether the record is scientifically plausible and useful for curation or reuse. Only the first two levels can be addressed mainly by automated schema and grounding tools; the latter two require provenance and human review \cite{diaz2025knowledgegraphs,rankovic2025uncertainty,walls2025catminer}.

However, schema validation should not be confused with scientific validation. A record may satisfy JSON Schema and SHACL while still being wrong because the source passage was parsed incorrectly, a value was copied from a model result rather than an experiment, or a catalyst abbreviation was resolved to the wrong material. For this reason, current systems combine structural checks with provenance and confidence information. Extracted entities and triples should retain links to the publication, paragraph, table, or evidence passage from which they were derived, so that curators can inspect and correct the original basis of a claim \cite{diaz2025knowledgegraphs}. Confidence scores can be used to prioritize review, while low-confidence or constraint-violating records can be held back from automatic ingestion \cite{zhang2022knowledge,rankovic2025uncertainty}.

The main lesson for semantic metadata extraction is therefore that validation is not a single pass at the end of the workflow. It is a feedback loop: schema tools catch machine-readable inconsistencies, provenance supports traceable correction, confidence estimates help allocate expert attention, and human reviewers decide whether the structured statement is actually supported by the evidence. This combination is necessary because many quality problems originate upstream in the literature itself, including incomplete reporting, missing negative results, ambiguous terminology, and brittle PDF or table parsing \cite{mendes2025data,takahashi2023catalysts,salim2026methane,walls2025catminer}. Human-in-the-loop validation thus forms the practical boundary between automated extraction and trustworthy catalysis research data.

\section{Research Gap}
\label{sec:research-gap}
The reviewed literature shows that the central research gap is not the absence of individual building blocks. Catalysis research already has important infrastructure initiatives, repository concepts, vocabularies, ontology surveys, and emerging metadata profiles. ChemDCAT-AP, Voc4Cat, Ontologies4Cat, Repo4Cat, and the broader NFDI4Cat ecosystem demonstrate that catalysis data can be described with increasing semantic precision \cite{wulf2021unified,nfdi4cat2024whitepaper,stroemert2026chemdcat,veluvali2025bridging,behr2024ontologies4cat}. At the same time, these building blocks do not yet amount to a practical, widely adopted workflow that turns heterogeneous experimental descriptions into validated, schema-aligned, human-reviewable metadata records. The semantic models provide a target structure, but the acquisition of trustworthy data for this structure remains difficult.

This acquisition gap is visible both in publications and in dataset-level material. Existing NLP and LLM systems can extract entities, relations, catalyst names, performance values, and operating conditions, but the extracted information is often still close to the wording and layout of the source text \cite{zhang2022knowledge,walls2025catminer}. For experimental catalysis, this is not sufficient because relevant information may be distributed across synthesis descriptions, characterization sections, reaction-condition tables, figures, captions, supplementary files, instrument exports, and local metadata files. CatMiner shows that inter-paragraph context and the distinction between experimental and computational results are important for heterogeneous catalysis extraction, while broader catalysis data discussions emphasize that reporting remains incomplete, inconsistent, and frequently not machine-readable \cite{walls2025catminer,mendes2025data,salim2026methane}. As a result, extracted records require normalization, semantic grounding, and provenance before they can be treated as reusable research data.

A second gap concerns the connection between extraction and validation. General LLM-based extraction approaches and systems such as SPIRES show that structured prompting can populate schema-like records \cite{dagdelen2024structured,caufield2024spires}. Semantic infrastructures such as ChemDCAT-AP show that LinkML schemas can be compiled into JSON Schema, SHACL shapes, JSON-LD contexts, and Python/Pydantic classes \cite{stroemert2026chemdcat,chemdcatapDocumentation}. However, many workflows still treat these steps as separate: the LLM produces a structured output, and validation is applied afterwards as a technical check. For catalysis metadata, this separation is limiting because structural validity does not prove that a catalyst, reaction condition, measurement setting, or performance value is scientifically supported by the source. The workflow therefore has to combine schema validation, evidence tracking, confidence handling, and human review rather than relying on automatic generation alone \cite{diaz2025knowledgegraphs,rankovic2025uncertainty,w3c2017shacl}.

This thesis is positioned in this operational gap between semantic modelling and practical metadata acquisition. It does not aim to introduce a universal catalysis ontology or a fully automated literature database. Instead, it investigates how an LLM-supported workflow can extract semantic metadata from catalytic experiments, map the extracted information to a defined metadata structure, validate it with machine-readable constraints, and keep human correction in the loop. The contribution therefore lies in operationalizing existing ideas: semantic models become constraints for extraction, LLM outputs become traceable candidate records, and validation becomes a staged process before data are reused in a repository or knowledge graph. This focus leads directly to the methodical approach in Chapter~\ref{chap:requirements}, where the proposed workflow is decomposed into source handling, extraction, profile construction and validation, final semantic grounding, and evaluation.
